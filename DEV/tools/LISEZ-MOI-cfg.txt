cfg.json — LISEZ-MOI
=====================

Ce fichier explique chaque option de cfg.json. Le format JSON n'admet pas de commentaires : les explications sont ici.
Après toute modification de cfg.json, relancez Pesto. Ne mettez jamais de mot de passe dans cfg.json.
Vrai ou faux : "true" / "false" entre guillemets dans DEBUG et CONF ; true / false sans guillemets dans POLICY.
La plupart de ces options se règlent aussi dans Pesto : page Paramètres, puis « Enregistrer les paramètres ».


Configured
----------
true : configuration d'entreprise validée. false (modèle vierge) bloque Pesto sur la fenêtre d'import.


DEBUG — mode de fonctionnement et drapeaux de test (en service : tout à "false", c'est le mode réel)
-----
Simulation     "false" : opérations réelles (mise au domaine, renommage, déplacement).
               "true"  : simulation, rien n'est écrit dans l'AD ni sur le poste.
GUI            "true" : démonstration de l'interface, sans AD, valeurs fictives. "false" en service.
HorsDomaine    Test seulement : fait croire que le PC est hors domaine. Refusé en mode réel.
MauvaiseOU     Test seulement : fait croire que le poste est dans une mauvaise OU. Refusé en mode réel.
BPVerifNomAD   Réservé, sans effet. Laisser "false".
ForceADM       Réservé, sans effet. Laisser "false".


CONF — réglages métier (la liste contient exactement un objet)
----
Domaine        Domaine DNS de l'AD. Tous les DN des OU de ce fichier doivent appartenir à ce domaine.
ADM            Compte d'administration proposé à la connexion quand le PC est hors domaine.
               Le mot de passe se saisit à la connexion ; il n'est jamais écrit dans ce fichier.
Prefixe        Code du département, exactement 6 chiffres. Caractères 2 à 7 des noms :
               P123456PAINF001 = type P, département 123456, site PA, service INF, numéro 001.
PreprodSite    Code service (3 caractères) des noms donnés en zone de préparation (DirectProd "false").
               Malgré son nom, ce n'est pas un site.
DirectProd     "true"  : la mise au domaine place le PC directement dans l'OU de son site.
               "false" : dans l'OU PREPROD (voir OUBase) ; le PC rejoint ensuite son site par un renommage
               avec changement de site.
DarkMode       Thème par défaut : "0" clair, "1" sombre, "2" suivre Windows. Le choix de chaque utilisateur prime.
Buffer         Nombre de noms libres affichés au-delà du dernier numéro utilisé (0 à 999). Sans effet sur les opérations.
OUScanNoms     Racine de l'inventaire des noms (DN d'OU) ; vide = OU ROOT. Chaque nom est de toute façon
               revérifié dans tout le domaine juste avant l'opération.
EntraPolicy    "HybridOnly" (défaut) : avant un renommage, retrait Entra seulement si le poste est confirmé hybride.
               "Disabled" : jamais de retrait Entra.
ClearProtectionOnMove
               "true" (défaut) : un objet protégé contre la suppression accidentelle est déprotégé le temps du
               déplacement, puis reprotégé et relu. "false" : déplacement d'un objet protégé refusé (code 31).
DsregLeaveOnMove
               Ancien réglage, ignoré : un déplacement d'OU ne lance jamais dsregcmd /leave.


TAGS — code de 2 lettres du site dans les noms de postes
----
Site           Nom ou motif du site (jokers * et ?, sans distinction de casse, sans doublon).
Tag            Exactement 2 lettres.
Quand DirectProd vaut "false", un motif doit couvrir PREPROD ou le code PreprodSite. Un site sans motif reçoit
un code de repli calculé par Pesto et signalé dans le Journal : ajoutez une ligne par site pour fixer son code.
Exemple : { "Site": "Marseille Prado", "Tag": "MP" }


OUBase — OU de base
------
ROOT           Racine des postes gérés par Pesto (obligatoire).
PREPROD        OU de préparation (obligatoire quand DirectProd vaut "false").


OUSite — organismes
------
Nom            Nom affiché dans Pesto.
OU             DN de l'OU qui contient les OU de site de cet organisme (une OU par site, nommée comme le site).


NameCatalogue — facultatif
-------------
Combinaisons Site (2 lettres) et Service (3 caractères) proposées dans les outils de noms même si aucun poste ne
les porte encore. Exemple : [ { "Site": "PA", "Service": "INF" } ]. Seules les clés Site et Service sont admises.


POLICY — politique d'exploitation (schéma fermé : toute clé inconnue est refusée)
------
Les valeurs livrées sont les valeurs par défaut : même comportement que sans POLICY.
Modèle complet avec des valeurs fictives : cfg.modele-complet.json (à côté de ce fichier).
Schema                     Obligatoire, vaut 1.
ExcludedNames              Noms de postes jamais modifiés : lettres, chiffres, tiret, jokers * et ?,
                           64 caractères au plus, 200 entrées au plus. Exemple : [ "P123456*SRV*" ].
ExcludedOUs                OU dont les postes ne sont jamais modifiés (DN complets, 200 au plus).
ExcludedGroupGuids         GUID des groupes AD dont les membres (directs et imbriqués) ne sont jamais modifiés.
CoordinationRoot           Dossier partagé qui coordonne plusieurs techniciens (chemin absolu, 240 caractères
                           au plus). Vide = pas de coordination.
CoordinationRequired       true : la configuration est refusée sans dossier partagé (CoordinationRoot).
AllowPasswordTaskFallback  true : après un refus confirmé, repli par tâche Windows utilisant le mot de passe du
                           compte AD. Jamais sur un résultat incertain.
AllowPrecreatedJoin        true : case « Utiliser un compte ordinateur précréé » à la mise au domaine.
AllowOfflineJoin           Doit rester false (jonction hors connexion non disponible).
MaxReaders                 Lectures AD simultanées, de 1 à 8 (défaut 4).
ReadAttempts               Tentatives par lecture AD, de 1 à 3 (défaut 2).
MaxBatch                   Postes par lot, de 1 à 200 (défaut 200).
NameReservationMinutes     Durée d'une réservation de nom dans le dossier partagé, de 5 à 240 minutes (défaut 15).
                           Prolongée tant que le nom reste proposé ; libérée après l'opération.
ReserveNamesInAD           false par défaut. true : à la mise au domaine, Pesto crée le compte ordinateur après la
                           vérification et avant la confirmation ; la jonction reprend ce compte identifié par GUID.
                           Un retrait après annulation ou refus exige le GUID, le marqueur exact et l'emplacement
                           attendus, sans nom DNS ni SPN. Un objet modifié ou un résultat incertain reste à vérifier.
                           Fermer Pesto ne supprime aucun compte réservé. Le reçu est conservé dans
                           %ProgramData%\GP\Join\ad-reservation.json ; ne le supprimez pas pour contourner un blocage.
                           Au lancement suivant, cliquez sur « Vérifier l’état » pour relire la réservation.
                           Cette inspection n'écrit pas dans AD et ne lance pas la jonction : relisez le nom proposé,
                           vérifiez le formulaire puis confirmez séparément l'ajout. Une autre machine, un autre
                           domaine ou contrôleur empêche la reprise. Si le résultat reste incertain, contactez l'administrateur.
RandomNameEnabled          true par défaut : tirage uniforme parmi tous les noms libres correspondant aux filtres.
                           La page et la marge affichées ne limitent pas ce choix. false : premier nom libre.
                           RandomNameChoice reste accepté à l’import : 0/1 désactive, 2..50 active le tirage complet.
                           Enregistrer écrit uniquement RandomNameEnabled ; deux réglages contradictoires sont refusés.

Plusieurs techniciens en même temps : CoordinationRoot = dossier partagé du registre des réservations (par exemple
\\serveur\partage\Pesto, à préparer dans Paramètres > Noms et coordination > « Préparer ce dossier »). Avec un dossier
indiqué, Pesto y réserve chaque nom proposé et y pose un verrou au moment d'agir ; s'il est injoignable, l'opération est
refusée avant toute écriture. Vide = pas de registre.


Anciens réglages acceptés mais sans effet : MoveRollbackOnRenameFail, AllowHybridRepair (remplacé par
EntraPolicy), DsregLeaveOnMove.
LogRetentionDays           Conservation des journaux : 30 jours par défaut, de 0 à 3650. 0 désactive la purge ; reçus conservés.
UnattendedJoinEnabled      false par défaut. true autorise Invoke-PestoAutoJoin.ps1 pour task sequence ; -Execute reste obligatoire.
                           Voir le guide administrateur : PSCredential en mémoire, Windows PowerShell 5.1 x64 élevé, pas de redémarrage automatique.
