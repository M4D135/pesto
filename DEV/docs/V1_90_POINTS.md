# Pesto 1.0 : suivi des 90 propositions

**Statut : BROUILLON.** Base : `RC23_90_POINTS.md`, reprise ligne par ligne.

## Règle appliquée

- **Les statuts de code restent ceux de la RC23.** Un statut ne change que sur preuve. La 1.0 a depuis tourné sous Windows PowerShell 5.1 en VM et en WPF interactif (recette partielle des 2–4 octobre) ; UAC acceptée/refusée prouvée le 04/10 ; AD réel non prouvé. Voir `V1_RECETTE_WINDOWS.md` pour les résultats actuels, sans déduire une clôture des 90 points.
- « Livré » signifie toujours « code raccordé dans le paquet », pas « scénario accepté sous Windows ».
- La colonne « Preuve d'exécution » dit ce qui a réellement tourné, où et sur quel commit. « Hôte » désigne le PC
  Windows 11 du labo (`DESKTOP-285EKHU`, Windows PowerShell 5.1.26100), en SSH sans bureau. Ce n'est pas la VM du
  domaine. Le commit `c2e62e2` précède les points B, C, E et la 1.0.
- Mentions « **1.0 :** » : changements de code de la 1.0 qui touchent le point, sans changer son statut.

## Fait à garder en tête

La RC23 reçue **ne démarrait pas** : erreur de syntaxe dans `Get-SiteTag` (D4), puis écriture de `$HOME` (F2). Ses
statuts « Livré » décrivaient donc du code qu'aucun Windows n'avait pu exécuter. Les 122 tests Python et les 340
contrôles portables étaient verts malgré cela : ils contrôlent des chaînes dans les sources, pas le comportement.
