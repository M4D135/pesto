# Refonte Pesto — candidat 2.0.16

## Périmètre

La branche `codex/pesto-performance-rename-20261113` poursuit la remise en état des lectures sites/services et du renommage. Le format reste `Pesto.exe` + `wad/`, avec `wad/support/DEBLOQUER_TOUT.cmd`. Cette version de source ne constitue pas à elle seule une release publiée ni une qualification sur un domaine réel.

Le commit `bfbe2e9b1094236f1b8717a0aaab24b05cb39501` restaure l’arbre complet du dépôt après un arbre incomplet, sans réécriture d’historique et sans perdre les quatre derniers correctifs web. Le diff avec le dernier arbre complet ne comporte que ces quatre fichiers modifiés.

## Correctifs de cette passe

- Le champ service de jonction et de renommage respecte la largeur configurée (1 à 6 caractères), reçue avec la liste des sites ; aucun appel de configuration ou AD supplémentaire. Une modification invalide immédiatement l’ancien aperçu. Les suggestions restent facultatives ; la préproduction garde sa destination et son service imposés.
- Les filtres de services sont construits depuis les jetons de la convention, et non par découpe d’un code site supposé long de deux caractères. Ils conservent le préfixe, le type et les séparateurs. Deux recherches bornées demeurent : tous les sites de l’organisme dans l’OU sélectionnée, et le tag sélectionné dans le domaine. Aucune recherche générale de remplacement.
- Les tests DOM distinguent la liste de « Noms disponibles » des champs libres de jonction/renommage.
- Les trois déclarations de version passent ensemble à 2.0.16. Le runtime, les dépendances épinglées, le kit graphique et la configuration opérateur ne changent pas.

## Contrôles et limites

La CI du commit restauré `bfbe2e9` a réussi 731 tests moteur, 15 tests du pont et 77 contrôles métier Chromium, puis a échoué sur le sélecteur DOM corrigé ici. Ces résultats ne qualifient pas les ajouts suivants.

Les nouveaux cas couvrent les largeurs de service, les conventions réordonnées, les préfixes courts, les sites de quatre caractères et les filtres LDAP invalides. Les contrôles portables web, métadonnées, cycle du pont et démonstration ont été exécutés localement. La compilation .NET, le parseur Windows PowerShell 5.1, les fixtures AD synthétiques et les suites Chromium complètes doivent passer dans la CI du nouveau commit avant livraison de son archive.

Les archives restent `distribution=candidate`, `official=false`, `qualification=unqualified`, avec SHA source et empreintes enregistrés par le workflow. La validation interactive Windows et AD appartient à l’essai manuel de l’utilisateur : aucune campagne VM, aucun renommage ni déplacement sur un domaine réel n’a été exécuté pour cette passe. La release 2.0.15 reste distincte tant qu’une nouvelle publication n’a pas été effectivement vérifiée.
