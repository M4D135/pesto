

Verdict ciblé : il reste des trous concrets côté persistance/reprise, surtout sur `install`, `uninstall`, `_replace_from`, `apply_update` et `recover_update`. Les tests actuels sont bons sur le rollback “in-process”, mais ils ne couvrent pas assez la suppression d’une destination existante, le crash d’un désinstall, le nettoyage des backups de préparation, et le kill externe aux frontières.

Je ne qualifie pas AD/SMB/coupure secteur. Les propositions ci-dessous simulent un arrêt brutal du processus (`os._exit`, `proc.kill()`), pas une coupure physique.

## Bugs concrets à corriger

### 1. `managed_install.install()` peut détruire une installation existante

Fichier : `DEV/tools/managed_install.py`

```python
def install(source, destination):
    destination = Path(destination)
    build_directory(Path(source), destination, 'PROD')
    try:
        ...
    except BaseException:
        shutil.rmtree(destination)
        raise
```

Problème :

- `install()` ne refuse pas une destination déjà existante.
- Si `build_directory()` échoue après avoir touché une destination existante, `shutil.rmtree(destination)` supprime tout.
- Le commentaire “Only the directory created by this invocation can be removed here” n’est pas garanti par le code.

Correctif :

```python
def install(source, destination):
    destination = Path(destination)

    if _is_link_or_junction(destination):
        raise ValueError('Linked destination refused')
    if destination.exists():
        raise ValueError('Destination must not exist')

    build_directory(Path(source), destination, 'PROD')
    try:
        receipt = make_receipt(
            destination,
            runtime_files(destination),
            verify_runtime(destination)['Version'],
        )
        atomic_write_json(destination / RECEIPT, receipt)
    except BaseException:
        shutil.rmtree(destination, ignore_errors=True)
        raise
    return receipt
```

Il faut aussi rendre l’écriture du receipt atomique/durable.

### 3. `changed_owned_files()` explose sur un fichier manquant

Fichier : `DEV/tools/installation_receipt.py`

```python
def changed_owned_files(root, receipt):
    return [path for path, digest in receipt['files'].items()
            if file_hash(safe_file(root, path)) != digest]
```

Problème :

- Si un fichier owned est manquant, `safe_file()` ou `file_hash()` peut lever une exception.
- `detect()` devrait alors retourner `healthy: false` avec `changed` contenant le fichier manquant.
- Actuellement, un état “partiellement supprimé” peut devenir une traceback au lieu d’un diagnostic propre.

Correctif : introduire un digest tolérant aux fichiers absents.

```python
from refresh_manifest import validate_relative

def _owned_digest(root, relative):
    validate_relative(relative)
    root = Path(root)
    target = root / relative

    for item in (target, *target.parents):
        if item == root:
            break
        if _is_link_or_junction(item):
            raise ValueError('Linked owned file refused: ' + relative)

    try:
        resolved = target.resolve(strict=False)
    except OSError as exc:
        raise ValueError('Cannot resolve owned file: ' + relative) from exc

    if root not in resolved.parents and resolved != root:
        raise ValueError('Owned file escapes root: ' + relative)

    if not target.is_file():
        return None

    return file_hash(target)


def changed_owned_files(root, receipt):
    return [
        path
        for path, digest in receipt['files'].items()
        if _owned_digest(root, path) != digest
    ]
```

Avec ça :

- fichier absent => digest `None`
- digest attendu non `None` => fichier considéré comme changed
- lien/jonction refusé => exception explicite
- `detect()` peut retourner `healthy: false` proprement

### 4. `detect()` devrait retourner un état non sain au lieu de lever sur receipt invalide

Fichier : `DEV/tools/managed_install.py`

Actuellement :

```python
receipt = load_receipt(root, runtime_files(root), required=True)
...
if receipt['version'] != manifest['Version']:
    raise ValueError('Installation receipt version differs')
```

Problème :

- Un receipt partiel, invalide, ou une version incohérente peut lever une exception.
- Pour un outil de management, `detect` devrait retourner `installed: true, healthy: false, reason: ...`.

Correctif :

```python
def detect(destination):
    root = Path(destination)

    if not root.exists():
        return {'installed': False, 'healthy': False, 'reason': 'absent'}

    if _is_link_or_junction(root):
        return {'installed': False, 'healthy': False, 'reason': 'linked root'}

    receipt_path = root / RECEIPT
    if not receipt_path.exists() and not _is_link_or_junction(receipt_path):
        return {
            'installed': False,
            'healthy': False,
            'reason': 'unmanaged or removed; data retained',
        }

    try:
        receipt = load_receipt(root, runtime_files(root), required=True)
    except ValueError as exc:
        return {
            'installed': True,
            'healthy': False,
            'reason': 'invalid receipt: ' + str(exc),
            'changed': [],
            'owned': [],
        }

    try:
        changed = changed_owned_files(root, receipt)
    except ValueError as exc:
        return {
            'installed': True,
            'healthy': False,
            'reason': 'invalid owned file: ' + str(exc),
            'changed': [],
            'owned': sorted(receipt['files']),
        }

    if not changed:
        try:
            manifest = verify_runtime(root)
        except ValueError as exc:
            return {
                'installed': True,
                'healthy': False,
                'reason': 'invalid runtime: ' + str(exc),
                'changed': [],
                'owned': sorted(receipt['files']),
            }

        if receipt['version'] != manifest['Version']:
            return {
                'installed': True,
                'healthy': False,
                'reason': 'receipt/runtime version mismatch',
                'changed': [],
                'owned': sorted(receipt['files']),
            }

    return {
        'installed': True,
        'healthy': not changed,
        'version': receipt['version'],
        'changed': changed,
        'owned': sorted(receipt['files']),
    }
```

### 5. `uninstall()` laisse un fence non récupérable après crash

Fichier : `DEV/tools/managed_install.py`

```python
fence = root / '.pesto-update.lock'
with fence.open('xb') as stream:
    stream.write(b'{"Stage":"ManagedUninstall"}')
```

Problèmes concrets :

1. Le fence est écrit sans `fsync`.
2. En cas de crash pendant la suppression, le fence reste.
3. `plan_recovery()` ne connaît que `Preparing` et `Copying`.
4. Donc une mise à jour future est bloquée sur `.pesto-update.lock`.
5. La suppression des fichiers n’est pas durable : pas de `fsync` des répertoires.

Correctif :

- écrire un fence `ManagedUninstall` durable ;
- ajouter une récupération explicite dans `plan_recovery()` / `recover_update()` ;
- fsync après chaque unlink.

Dans `managed_install.uninstall()` :

```python
import os
from update_installation import create_json_exclusive, _fsync_directory
from refresh_manifest import file_hash


def uninstall(destination, execute=False, *, _crash_after: int | None = None):
    root = Path(destination).absolute()
    result = detect(root)

    if not result['installed']:
        return result
    if not result['healthy']:
        raise ValueError('Modified installed code: nothing removed')

    plan = {
        'remove': result['owned'] + [RECEIPT],
        'preserve': ['wad/cfg.json', 'all unowned files', 'all GP user/system profiles'],
        'executed': False,
    }

    if not execute:
        return plan

    again = detect(root)
    if not again['healthy'] or again['owned'] != result['owned']:
        raise ValueError('Installation changed during preparation')

    with mutation_guard():
        check_local_states()

        fence = root / '.pesto-update.lock'
        fence_value = {
            'Schema': 1,
            'Stage': 'ManagedUninstall',
            'Destination': str(root),
            'Owned': plan['remove'],
            'ReceiptSHA256': file_hash(root / RECEIPT),
        }

        create_json_exclusive(fence, fence_value)

        try:
            for index, relative in enumerate(plan['remove'], 1):
                try:
                    target = safe_file(root, relative)
                except FileNotFoundError:
                    pass
                else:
                    if target.exists():
                        target.unlink()
                        _fsync_directory(target.parent)

                if _crash_after is not None and index == _crash_after:
                    os._exit(96)
        except BaseException:
            raise
        else:
            fence.unlink(missing_ok=True)
            _fsync_directory(root)

    plan['executed'] = True
    return plan
```

`_crash_after` est un hook de test, pas une option CLI.

### 8. `_replace_from()` ne fsync pas le répertoire après remplacement

Fichier : `DEV/tools/update_installation.py`

Actuellement :

```python
shutil.copyfileobj(stream,out);out.flush();os.fsync(out.fileno())
...
os.replace(name,target)
```

Problème :

- Sur POSIX, `os.replace()` est atomique, mais la visibilité durable de l’entrée de répertoire nécessite un `fsync` du répertoire parent.
- Sans ça, un arrêt brutal peut laisser un état ambigu entre ancien et nouveau fichier.

Correctif :

```python
def _replace_from(source: Path, target: Path) -> None:
    target.parent.mkdir(parents=True, exist_ok=True)
    fd, name = tempfile.mkstemp(prefix='.pesto-copy-', suffix='.tmp', dir=target.parent)

    try:
        with os.fdopen(fd, 'wb') as out, source.open('rb') as stream:
            shutil.copyfileobj(stream, out)
            out.flush()
            os.fsync(out.fileno())

        if target.exists():
            if os.name == 'nt':
                _replace_windows_preserving_acl(name, target)
            else:
                os.chmod(name, stat.S_IMODE(target.stat().st_mode))
                os.replace(name, target)
        else:
            if os.name != 'nt':
                os.chmod(name, stat.S_IMODE(source.stat().st_mode))
            os.replace(name, target)

        _fsync_directory(target.parent)
    finally:
        if os.path.exists(name):
            os.unlink(name)
```

Bonus : sur POSIX, les nouveaux fichiers créés par `mkstemp()` sont en `0600`. Il faut au moins préserver le mode de la source pour les nouveaux fichiers.

### 9. `apply_update()` peut laisser des backups orphelins en préparation

Fichier : `DEV/tools/update_installation.py`

Actuellement :

- le backup est créé après le fence `Preparing` ;
- si crash pendant la préparation, `plan_recovery()` ne connaît pas le backup ;
- si exception avant journalisation, `finally` retire le lock mais pas le backup.

Correctif :

1. Créer un chemin de backup déterministe.
2. Écrire le chemin dans le fence `Preparing`.
3. Créer le backup après avoir persisté le fence.
4. Nettoyer le backup si aucune copie vers la destination n’a commencé.

Helper :

```python
def create_json_exclusive(path, value):
    path = Path(path)
    fd = os.open(path, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o600)

    with os.fdopen(fd, 'wb') as stream:
        stream.write(json.dumps(value, ensure_ascii=False, sort_keys=True).encode('utf-8'))
        stream.flush()
        os.fsync(stream.fileno())

    _fsync_directory(path.parent)
```

```python
def test_external_kill_at_each_copy_boundary(self):
    for boundary in range(1, self.boundaries() + 1):
        with self.subTest(boundary=boundary):
            marker = self.base / f'pause-{boundary}'

            code = (
                'import sys,contextlib,json;from pathlib import Path;'
                'sys.path.insert(0,sys.argv[1]);import update_installation as u;'
                'u.mutation_guard=contextlib.nullcontext;'
                'u.check_local_states=lambda:None;'
                'u._check_pesto_session_lock=lambda p:None;'
                'u.apply_update(Path(sys.argv[2]),Path(sys.argv[3]),**json.loads(sys.argv[4]))'
            )

            proc = subprocess.Popen(
                [
                    sys.executable,
                    '-c',
                    code,
                    str(ROOT / 'tools'),
                    str(self.new),
                    str(self.dest),
                    json.dumps({
                        '_pause_after': boundary,
                        '_pause_marker': str(marker),
                    }),
                ],
                stdout=subprocess.PIPE,
                stderr=subprocess.PIPE,
                text=True,
            )

            deadline = time.time() + 30
            while not marker.exists():
                if time.time() > deadline:
                    proc.kill()
                    proc.wait()
                    self.fail('pause marker was not created')
                time.sleep(0.01)

            proc.kill()
            proc.wait()
            marker.unlink()

            self.assertTrue((self.dest / '.pesto-update.lock').is_file())

            preview = update.recover_update(self.dest)
            self.assertEqual(preview['Kind'], 'RestorePreviousCodeOnly')
            self.assertFalse(preview['Conflicts'])

            self.assertTrue(update.recover_update(self.dest, apply=True)['Recovered'])
            self.assert_old()

            for backup in self.base.glob('installed-code-backup-*'):
                shutil.rmtree(backup)
```

Ce test est déterministe parce que :

- la frontière est fixe ;
- l’enfant marque le point exact après remplacement ;
- le parent ne tue qu’après apparition du marqueur ;
- la reprise est vérifiée immédiatement.

## Limites assumées

Ces correctifs ne prétendent pas :

- qualifier AD/SMB ;
- simuler une coupure électrique réelle ;
- garantir une transaction OS atomique multi-fichiers ;
- empêcher Pesto de se rouvrir juste après `_check_pesto_session_lock()` ;
- résoudre les receipts d’opération concurrents hors du périmètre de ces outils.

Ils réduisent les fenêtres de persistance/reprise entre effets filesystem, qui sont le point concret restant.
