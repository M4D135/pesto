### 1. Revue Technique & Correctifs (PowerShell 5.1 / C#5 / Sécurité)

J'ai analysé les fichiers fournis. Le code est globalement robuste pour la cible PS 5.1. Voici les points critiques identifiés et les correctifs précis à appliquer **avant** de lancer les tests VM.

#### A. Bugs de Compatibilité & Logique (PowerShell 5.1)

**1. `DEV/tests/Run-SecretOutputsTests.ps1` : Risque de variable non initialisée**
*   **Problème :** Dans le bloc `Case 'Masked diagnostics...'`, tu définis `$script:BasePath=$null` mais tu ne déclares pas `$BasePath` en scope local ou global avant usage dans certaines fonctions internes si elles s'y attendent. Plus critique : l'objet `$receipt` est créé avec des champs comme `Plan` qui contiennent `$payload` (le secret). Si une fonction interne tente d'accéder à `$Receipt.Plan.Reference` sans passer par `Protect-PestoLogText`, le secret fuite.
*   **Vérification :** La fonction `Get-PestoOperationSupport` (dans `Pesto-ReceiptTools.ps1`) a été corrigée dans le diff pour utiliser `Protect-PestoLogText` sur `Reference`. C'est bon.
*   **Correctif mineur :** Dans `Run-SecretOutputsTests.ps1`, assure-toi que `$script:OUV` est bien un hashtable vide (`@{}`) et non `$null` si les fonctions de diagnostic itèrent dessus. C'est déjà le cas (`$script:OUV=@{}`).
*   **Action :** Aucun correctif de code nécessaire ici, la logique de protection est en place.

**2. `DEV/tools/Measure-PestoWpfSession.ps1` : Gestion des AssemblyNames**
*   **Problème :** `Add-Type -ReferencedAssemblies @(..., 'System.dll')`. En PS 5.1, `System.dll` est souvent résolu automatiquement, mais l'ajout explicite est bon. Par contre, `System.Xaml` est requis pour `XamlReader`.
*   **Vérification :** Le script ajoute bien `System.Xaml`.
*   **Action :** OK.

**3. `DEV/wad/Pesto-Support.ps1` : Affichage de l'étape**
*   **Diff :** `$w.FindName('ErrorStage').Text='Étape : '+$info.Stage` remplace l'usage direct de `$Stage`.
*   **Analyse :** C'est une correction de sécurité majeure. `$info.Stage` est le résultat de `Protect-PestoLogText $Stage`. Cela empêche l'injection de secrets dans l'UI WPF.
*   **Action :** **Valider ce correctif.** Il est essentiel.

#### B. Fuites de Secrets (Canary Test)

Le test `Run-SecretOutputsTests.ps1` utilise un canary `PESTO_SYNTHETIC_SECRET_106_ONLY`.
*   **Point critique :** La fonction `Get-PestoTicketText` (dans `Pesto-Workspace.ps1`) a été modifiée pour retourner `Protect-PestoLogText ($lines -join ...)`.
*   **Risque résiduel :** Si `Get-PestoNativeGuidance` ou d'autres fonctions internes ajoutent du texte brut contenant des données sensibles *avant* la jointure, `Protect-PestoLogText` ne masquera que ce qui est passé en paramètre final.
*   **Vérification :** `Protect-PestoLogText` est-il robuste ? Il doit remplacer les patterns connus (password, token, etc.). Si le canary est une chaîne simple, il doit être détecté.
*   **Action :** Le test `Case 'Internal ticket keeps useful identity and filters credential-like text'` vérifie que `PC-OLD` est présent mais que le secret est masqué. Si ce test passe en local, la protection est active.

### 3. Documentation v1.0 (Brouillon)

**Titre :** Pesto - Guide d'Utilisation et de Validation v1.0

**1. Introduction**
Pesto est un outil de gestion de poste Windows (Rename, Move, Join) conçu pour les environnements d'entreprise. Cette version v1.0 est destinée à la validation interne.

**2. Prérequis**
*   Windows 10/11 ou Windows Server 2019+.
*   PowerShell 5.1.
*   Accès AD (si opération de domaine).

**3. Installation**
*   Copier le dossier `DEV` sur le poste cible.
*   Exécuter `DEV/tools/Test-PestoEnvironment.ps1` pour vérifier l'intégrité des composants.

**4. Utilisation Basique**
*   Lancer `Pesto.exe` ou le script principal.
*   Utiliser l'onglet **Rename** pour changer le nom du PC.
*   Utiliser l'onglet **Move** pour déplacer l'objet AD.
*   **Important :** Toujours vérifier le "Receipt" (reçu) généré après chaque opération.

**5. Sécurité et Confidentialité**
*   Pesto masque automatiquement les secrets (mots de passe, tokens) dans les logs et l'interface.
*   Les rapports de diagnostic (`Get-PestoDiagnosticText`) sont masqués par défaut. Utilisez `-Redact $false` uniquement en interne et avec prudence.

**6. Validation**
*   Les tests automatisés (`Run-AllTests.ps1`) doivent passer avant toute mise en production.
*   Les tests manuels (checklist ci-dessus) sont requis pour la qualification finale.

**7. Limites Connues**
*   La validation visuelle sur des résolutions très élevées (4K+) nécessite un test manuel.
*   La compatibilité avec WDAC strict nécessite une signature certifiée.
